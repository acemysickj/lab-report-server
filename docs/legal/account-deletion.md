# 删除账号机制说明（注销与数据删除）

- 文档版本：v1.0-draft（COM-002-A 产出，P-007）
- 关联文档：《隐私政策》privacy-policy.md 第 8 节、《服务协议》terms-of-service.md 第 2.4 条

> 本文档面向用户（正文第一、二节）与实现方（第三节，给 COM-002 Auth / COM-003 Wallet 的落地口径）。〔运营确认〕标注的时限为建议口径。

---

## 一、用户须知：注销会删除什么

注销账号执行数据删除，具体范围：

| 数据 | 处理方式 |
| --- | --- |
| 账号信息（邮箱、密码哈希、告知勾选记录） | **删除或匿名化**：移除可直接识别您身份的字段，仅保留不可识别的占位记录以维持账务数据完整性 |
| 登录会话与设备标识 | **全部删除**：所有登录令牌立即作废，会话与设备标识记录删除 |
| 用户运行数据（AI 任务元数据、幂等键） | **删除**（AI 任务元数据随 90 天上限或注销时点先行删除；幂等键即时删除） |
| 内容文件（讲义/报告/图片） | 服务器本就不持久化存储，无需删除；客户端本地文件由您自行处理 |
| 交易与账务记录（订单、额度流水、退款记录） | **依法留存**：自交易完成之日起不少于三年；留存期间与您的身份标识解绑（匿名化），不再能关联到您 |
| 安全与运行日志 | 按 7–30 天保留期滚动清除，不做定向改写 |

**注销前请注意**：

1. 账号内未使用额度在注销后视为放弃、不予退还（《服务协议》第 3.4 条），法律另有强制性规定的除外。〔运营确认〕
2. 注销后原邮箱可重新注册，但新账号与历史账务记录不再关联。
3. 注销不可撤销，请确认后再操作。

## 二、注销流程（用户视角）

1. **入口**：客户端「账号设置 → 注销账号」；或发送邮件至【运营者联系邮箱】申请人工注销。
2. **核验**：需在登录状态下输入密码确认。若忘记密码，因首版不提供邮箱验证，将走人工账号恢复/注销路径：提供注册信息与历史交易凭证，人工核验后处理。
3. **确认告知**：展示上表删除范围与注意事项，二次确认。
4. **执行**：核验通过后及时执行，目标不超过 15 个工作日完成。〔运营确认〕
5. **结果反馈**：客户端内注销完成后立即退出登录；邮件申请的，处理结果回复至您的邮箱。
6. **投诉通道**：对注销处理结果不满的，可回复邮件申诉，或向履行个人信息保护职责的部门投诉。

## 三、实现口径（给 COM-002 / COM-003）

1. **触发接口**：注销须由服务端接口执行（登录态 + 密码再确认），不得仅靠客户端删除本地数据。
2. **删除范围对照 8 表**：
   - `users`：匿名化——邮箱、密码哈希等直接标识字段删除/置空；告知同意的时间与版本留痕保留（不含身份信息，作 P-002 合规证据）；保留不可识别占位行维持外键完整；
   - `auth_sessions`：整表按 user 删除，token family 立即作废；
   - `ai_jobs`：按 user 删除任务元数据；关联账务的扣费/退款事实保留在账务表中；
   - `idempotency_keys`：按 user 删除；
   - `credit_reservations`：释放/核销后清理；
   - `accounts`：余额清零并关闭；
   - `orders` / `credit_ledger`：**保留**（依法留存），关联的 user 标识经 users 匿名化后不再可识别。
3. **幂等与审计**：注销操作本身需幂等（重复请求返回同一结果）；建议在安全日志记录注销事件（仅含请求 ID、时间与结果，不含个人信息）。
4. **期限内数据一致性**：注销后任何接口不得再接受该账号的刷新令牌；进行中的 AI 任务按失败退款路径收尾后再执行删除，或直接作废并返还额度。〔实现时与 COM-003/COM-004 对齐〕
5. **对外措辞**：本机制对外表述为「注销执行数据删除：删资料/会话/用户数据，保留交易必要账务记录」，不得表述为「删除全部数据」。
